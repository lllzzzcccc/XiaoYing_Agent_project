# 复盘

## 最难的问题

最难的是让“模型决策”和“业务事实”保持边界：模型可以选择重规划，但费用、步骤状态、保存结果和最终完成状态必须来自实际工具与持久化状态。为此，方案指纹用于隔离失效结果，保存工具只接受 `plan_id`，最终化只读取权威运行状态。

跨进程续跑也暴露了一个实际问题：离线决策如果把上一轮失败当成本轮失败，就会在续跑时立即结束。通过记录本轮步骤边界，保留历史失败但允许新动作，才同时满足失败可追溯和续跑。

## 学习收获

- Pi `Agent` 的工具钩子、顺序执行和 Faux Provider 可以共享同一测试链路，但 Faux 证据不能替代真实模型证据。
- 测试先行能尽早发现输入日期、十进制边界、数据目录、Provider 类型和状态恢复问题。
- 幂等不能只防重复保存，还要保证原结果不被覆盖、冲突不写副作用、历史失败不被改写。
- 文档与验收追踪必须和实际文件同步，不能把预期结果写成实际结果。

## 下一步

1. 配置真实 Provider、模型和凭据，采集至少两条不同工具观察的真实路径。
2. 复核真实模型是否给出公开、简短且足够的决策说明，而不是依赖固定流程。
3. 如确需并发同 ID 执行，再单独评估本地锁范围；当前不引入生产级持久化。
4. 继续保持评估文档、实际证据和验收追踪一致。
