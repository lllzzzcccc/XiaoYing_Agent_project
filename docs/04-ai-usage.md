# AI 辅助使用说明

## 1. 说明目的

本文记录 AI 在本项目中的使用范围、候选人/用户的实际贡献、双方决策边界、验证方式及已知限制，便于评审判断哪些工作由 AI 辅助完成、哪些结果经过实际验证，以及哪些能力仍需进一步评估。

本项目涉及两类不同的模型用途：

- **开发辅助**：Kimi Code CLI 用于需求分析、技术方案、代码与测试编写、证据采集、文档整理和 Git 操作。
- **被验证的 Agent 模型**：DeepSeek `deepseek-flash` 通过 Pi Provider 执行业务工具调用，用于验证内容任务规划 Agent 的真实动态决策路径。

离线验证还使用了 Pi 官方 Faux Provider。Faux 只提供脚本化响应，不代表真实模型能力。

## 2. AI 使用范围

Kimi Code CLI 辅助完成了以下工作：

- 阅读原始笔试 HTML，提取第 2 题及通用交付要求。
- 按 SDD 完成 Specify、Plan、任务拆分和实施。
- 初始化 Node.js、TypeScript 和 Pi 项目并锁定依赖。
- 实现输入校验、费用与时间规则、本地请求存储、四个业务工具、运行状态、Trace、Pi Agent、CLI、跨进程防重复和失败续跑。
- 编写契约测试、集成测试、独立进程测试、证据检查和文档检查。
- 生成离线输入、实际输出、Trace、保存方案和证据索引。
- 使用真实 Provider 采集两条运行路径，并补充证据校验器。
- 编写 README、需求、方案、评估、AI 使用和复盘文档。
- 按用户授权进行 Git 提交、创建私有 GitHub 仓库并推送 `main`。

AI 生成的项目材料主要包括 `src/`、`tests/`、`data/`、`scripts/`、`specs/`、`docs/`、`examples/`、README、依赖配置和本文件。

## 3. 个人贡献与用户复核

候选人/用户并非只提供题目，其实际贡献包括：

1. **需求澄清**：确定 CLI、官方 Pi 包、模型配置方式、模拟费用、串行耗时、截止等值边界、JSON 输入和本地 JSON 保存。
2. **业务边界确认**：要求最终合计只计算当前方案、历史估算保留但不叠加、重试不额外计费、同 ID 不同输入报冲突、重复结果标记 `duplicate=true`。
3. **范围控制**：明确不引入生产级持久化、外部服务或无关功能。
4. **过程授权**：批准规格与 Plan 提交，授权按任务测试先行实施、提交及自主完成 T002–T018。
5. **外部条件提供**：在本地 `.env` 配置 DeepSeek Provider 和 `deepseek-flash`，使真实模型路径可以执行；提供 GitHub 仓库创建和推送授权。
6. **最终复核**：发现证据中仍有本机绝对路径，要求修正采集器和现有证据并增加防回归检查。

用户没有逐行提供实现代码，也未声明对所有代码进行人工逐行修改。架构和实现由 AI 按用户确认的规格完成，用户通过需求决策、外部配置和最终复核参与交付。

## 5. AI 作出的主要技术决策

在用户确认的范围内，AI 采用了以下设计：

- 以应用运行状态而非模型自述作为费用、步骤和保存结果的事实来源。
- 使用 Pi `Agent` 的顺序工具执行、前后钩子和事件流，不用固定分支或预设日志冒充 ReAct。
- 将内容活动方案与 Agent 运行步骤分开，使用方案指纹管理旧脚本和旧估算失效。
- 使用十进制模拟单位计算费用，最终只合计当前方案。
- 通过本地 JSON 和原子重命名实现跨进程防重复，不引入数据库或外部持久化。
- 保存工具只接受 `plan_id`，由权威状态组装保存内容，避免模型在保存参数中修改费用或输入。
- 使用 Pi 官方 Faux Provider 驱动同一离线工具链路，真实和 Mock 证据分开存放。
- 在证据输出边界规范化本机路径，不改变工具动作、状态和业务结果。

这些决策的详细理由见 `docs/02-solution.md` 和 `specs/plan.md`。

## 6. 测试先行的实际执行方式

每项行为任务按 RED → GREEN → REFACTOR → VERIFY 执行：

1. 先添加会因缺少功能或合同而失败的检查。
2. 实现满足检查的最小行为。
3. 重构共享规则，避免工具、CLI 和最终化出现不同口径。
4. 运行相关测试和全量回归，检查变更后提交。

实际发现并修正的问题包括：

- 缺少 manifest、lockfile 和 Pi 依赖时的初始化失败。
- TypeScript 类型与 Decimal 导入兼容问题。
- CLI 编译后数据目录指向错误。
- 续跑将上一轮失败误判为本轮失败的问题。
- 真实证据 manifest 的仓库相对路径被重复拼接的问题。
- 证据中残留本机绝对路径的问题。

没有把修正前的失败记录删除或改写成一次通过。

## 7. 验证结果与证据

当前主要验证结果如下：

- `npm ci` 和 TypeScript 构建通过，npm 审计 0 个漏洞。
- 全量 65 项测试通过，0 项失败。
- 采集 6 组离线实际场景及 1 组重复结果，全部明确标记 `mode=mock`。
- 使用 DeepSeek `deepseek-flash` 采集并校验 2 条真实路径：
  - 正常规划：检索、估算、脚本生成和保存均成功；
  - 保存失败：模型观察失败后重试，再次失败后停止，成功步骤保留，最终未完成。
- 独立读取保存 JSON、跨进程重复、同 ID 冲突和失败续跑均通过。
- 正常、重复执行和保存失败场景复核通过。
- 95 个跟踪文件未包含原始笔试 HTML、`.env` 或密钥文件。
- 证据本机绝对路径防回归检查通过。

证据入口：

- 离线清单：`examples/manifest.json`
- 真实清单：`examples/real/manifest.json`
- 评估记录：`docs/03-evaluation.md`
- 验收追踪：`specs/acceptance.md`

## 8. 数据、密钥与隐私边界

- 真实 `.env` 只通过 Node.js `--env-file` 机制供 Provider 使用，AI 未读取、打印或提交密钥。
- `.env`、密钥文件、原始笔试 HTML、`node_modules`、`dist` 和 `.runtime` 均由 `.gitignore` 排除。
- 业务素材和规则均为合成数据，没有接入真实发布、支付、采购或外部业务系统。
- Trace 只保留工具参数、结果摘要、后续动作和公开决策说明，不提交模型内部思维过程。
- 修正证据路径时只修改路径元数据，未改变工具动作、状态、费用、时间或业务结果。

## 9. AI 使用边界与未证明事项

以下结论不能仅凭本项目材料得出：

- 不能由 Faux 或离线正常结果推断真实模型在所有场景下都可靠。
- 本次只验证了 DeepSeek `deepseek-flash`，没有逐一验证其他 Provider 或模型。
- 两条真实路径证明不同工具观察会改变模型动作，但不构成对所有输入分布的泛化证明。
- 离线脚本由合成模板生成，不代表真实模型脚本质量。
- 当前实现只保证顺序跨进程防重复，不提供同 `request_id` 多进程并发锁。

真实模型证据也未被要求或用于证明隐藏推理正确性；评审应核对公开决策说明是否与工具观察及后续动作一致。

## 11. 后续人工评审建议

候选人/用户后续可重点复核：

1. 真实 Trace 中的模型动作是否确实由前一次工具观察触发。
2. 最终费用、耗时、保存状态和未完成原因是否与工具结果一致。
3. 真实与 Mock 证据是否始终分开陈述。
4. 重复、冲突和续跑是否保留原结果与失败历史。
5. 文档、证据和实际提交是否一致，是否还存在本机路径、密钥或隐私数据。
