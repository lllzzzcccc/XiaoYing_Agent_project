# 需求说明

## 用户与目标

目标用户为运营人员。系统帮助用户在给定预算和截止时间内形成并保存一份内容活动方案，最终结果必须能核对计划、步骤依赖、实际工具结果、费用、耗时、保存状态或未完成原因。

## 范围

- JSON 输入：`request_id`、非空主题、非负预算和含时区的合法 ISO-8601 截止时间。
- 合成素材、工具费用与耗时目录。
- 素材检索、脚本生成、成本估算、方案保存四类工具。
- 正常完成、输入不足或非法、无素材、工具失败、保存失败、预算超限、时间超限、部分成功、重复执行、请求冲突和执行上限。
- 本地 JSON 持久化与跨进程防重复；失败续跑为已实现的 P1 能力。

不包含真实发布、支付、采购、图形界面、线上部署、多 Agent、生产级 Runtime、数据库或外部持久化服务。

## 成功标准

只有当前方案满足预算和截止时间、有效脚本与方案指纹匹配、必需步骤成功且本地 JSON 保存成功后，整体状态才是 `completed`。其余情况必须返回 `incomplete` 和全部适用原因，不得把失败步骤或 Mock 结果虚报为真实成功。

至少两条真实模型路径应证明不同工具观察会改变后续动作；Mock 只验证流程，不证明真实模型决策效果。当前真实 Provider 路径受凭据与模型配置缺失阻塞，不能据此声明该项通过。

完整规格见 `specs/spec.md`，逐项状态见 `specs/acceptance.md`，实际结果和限制见 `docs/03-evaluation.md`。
