# 技术方案

## 架构与调用流程

CLI 解析 JSON 后，请求网关先检查 `request_id` 和输入指纹：重复请求返回原结果并标记 `duplicate=true`，同 ID 不同输入直接冲突。新请求进入 Pi `Agent`，由模型选择四个业务工具并观察实际结果。工具钩子只负责依赖、顺序、执行上限、运行状态和持久化，最终结果由应用状态确定性生成，而不是信任模型自述。

候选内容方案与 Agent 运行步骤分离。方案指纹变化时，旧脚本和估算保留但不再能用于当前保存。保存工具只接收 `plan_id`，从权威状态组装文件，防止保存参数篡改预算、费用或引用。

## 动态决策

真实模式下，Provider 返回的工具调用由 Pi 执行并回传结果。超预算、超时和无素材都是可观察结果，模型可选择替代方案、改写查询或停止；工具错误也原样反馈。离线模式使用 Pi 官方 Faux Provider 的脚本化响应驱动同一 Agent 和工具链路，并明确标记 `mode=mock`，不作为真实决策效果证据。

工具执行配置为 `sequential`。默认最多接受 12 次工具调用，失败和重试同样计数，达到上限后明确返回未完成。

## 费用、时间与保存

费用使用十进制模拟单位，最终合计只取当前方案最新成功估算；历史估算保留但不叠加，重试不额外计费。预计完成时间为任务开始时间加全部业务步骤串行耗时，等于截止时间也可行。预算缺口为最低费用候选方案减预算且最小为 0，预算和时间同时不可行时返回两项原因。

请求记录、方案和 Trace 使用本地 JSON/JSONL 及同目录临时文件原子重命名。P0 保证顺序跨进程防重复，不提供同 ID 并发锁。保存文件可独立读取，包含原始输入、当前方案、素材引用、脚本、费用、耗时和保存时间。

|---|---|---|

直接依赖使用精确版本，传递依赖由 `package-lock.json` 锁定。未引入 Web、数据库或多 Agent 框架。

## 已知限制

- 真实 Provider 运行需要外部凭据和模型配置，当前未提供，因此真实路径未验证。
- 离线脚本生成采用确定性合成模板，只引用已检索事实，不代表真实模型脚本质量。
- 不提供同 `request_id` 多进程并发互斥或跨主机一致性。
- 当前只支持文档列出的五类 Provider，其他 Provider 需要显式注册。
