# 内容任务规划 Agent 规格自查清单

本清单只检查 `specs/spec.md` 的完整性、一致性和可测试性。勾选表示规格文档已覆盖对应检查，不表示功能已经实现或验证通过；未勾选项表示仍有待确认事项。

## 1. 原题需求与已确认业务口径完整性

- [x] 明确目标用户为运营人员，目标是在预算和截止时间内完成内容活动方案。
- [x] 输入明确为 JSON，包含必填 `request_id`、主题、预算和截止时间。
- [x] 明确主题非空、预算非负、截止时间为含时区的合法 ISO-8601。
- [x] 列出合成素材、工具费用与耗时资料，覆盖素材检索、脚本生成、成本估算、方案保存四类工具。
- [x] 覆盖任务计划、步骤状态、工具结果、当前方案费用、历史估算、保存结果或未完成原因。
- [x] 覆盖正常完成场景 AC-001。
- [x] 分别覆盖缺预算和缺截止时间场景 AC-002、AC-003，并覆盖其他缺失或非法输入 AC-014。
- [x] 覆盖工具失败、部分成功和保存失败场景 AC-004、AC-005。
- [x] 覆盖超预算后有可行替代方案与无可行方案两种结果 AC-006、AC-007。
- [x] 覆盖无素材后的模型查询调整及仍无结果时的未完成场景 AC-015。
- [x] 覆盖跨进程重复执行 AC-009，要求返回原结果、标记 `duplicate=true` 且不重复保存。
- [x] 覆盖相同 `request_id` 不同输入的冲突场景 AC-018。
- [x] 将失败步骤续跑列为 P1 可选加分项，未误设为 P0 阻断项。
- [x] 明确失败步骤不得记为成功、保存失败不得声称已保存。
- [x] 明确重规划或失败后保留仍有效的成功结果，并处理结果失效的情况。
- [x] 明确初始方案超限后必须调整并重新估算，历史估算保留但不叠加，重试不额外计费。
- [x] 明确预算缺口公式，以及预算和时间同时不可行时返回两项原因。
- [x] 覆盖时间不可满足、完成时间等于截止时间和双重不可行场景 AC-008、AC-016、AC-017。
- [x] 明确本地 JSON 保存内容、等价口径和独立读取要求，并由 AC-019 验证。

## 2. 通用交付要求完整性

- [x] 技术栈限定为 Node.js + TypeScript，以及官方 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`。
- [x] 运行方式已确定为 CLI，并要求可复制的安装、配置和运行命令。
- [x] 模型通过 Pi Provider 和环境变量配置，依赖在初始化时确定并锁定版本。
- [x] 明确界面、线上部署、多 Agent、生产级 Runtime 非必需。
- [x] 覆盖至少一次“模型选择动作 → 工具执行 → 观察 → 模型调整或结束”的真实循环。
- [x] 明确固定条件分支、自动重试或预设日志不能单独满足动态决策要求。
- [x] 要求至少两条不同工具观察导致不同模型动作的真实执行路径。
- [x] Trace 字段覆盖步骤、工具参数、返回摘要、后续动作和简要决策依据。
- [x] 明确不提交模型内部思维过程，与简要决策依据记录不冲突。
- [x] 要求执行步数或工具调用次数上限，以及达到上限后的明确未完成状态。
- [x] 明确工具可使用本地函数或 Mock，模型不可用时提供离线 Mock 入口并说明边界。
- [x] 明确 Mock 仅验证流程，不能证明真实模型决策效果。
- [x] 要求至少三组输入、实际输出和运行记录，覆盖正常、信息不足、工具失败及全部验收点。
- [x] 要求实际输出和 Trace 位于 `examples/`，评估文档引用对应文件。
- [x] 要求可执行测试，并明确截图或视频不能替代代码和可执行验证。
- [x] 覆盖 README、源码、测试、示例、合成资料、依赖和 `.env.example` 的仓库要求。
- [x] 覆盖五份规定文档，以及 AI 使用、个人修改、验证、实际用时和未完成部分的记录要求。
- [x] 覆盖框架版本、使用功能和职责说明要求。
- [x] 覆盖题号、GitHub URL、最终 commit SHA 和私有仓库评审权限，具体值保留到提交阶段。
- [x] 明确所有材料在同一仓库，不提交真实密钥或隐私数据。

## 3. 一致性

- [x] “已完成”的定义同时要求满足预算、截止时间、必需步骤成功和保存成功，各场景未与此冲突。
- [x] 正常完成、保存失败、无可行方案和达到上限使用一致的完成状态语义。
- [x] 预算和截止时间均按硬约束处理，禁止系统擅自更改用户要求。
- [x] 时间规则统一使用任务开始时间加步骤串行总耗时，等于截止时间判定为可行。
- [x] 当前方案合计、历史估算保留和重试免费规则在各需求与场景中一致。
- [x] 预算缺口公式与 AC-007、AC-017 一致，双重不可行不再存在原因优先级歧义。
- [x] 工具结果、步骤状态和最终状态均要求据实反映，不允许预设成功日志。
- [x] 部分成功、结果保留、依赖阻断和失败续跑之间没有状态语义冲突。
- [x] 重复定义、`request_id` 规则、跨进程持久化、`duplicate=true` 和 AC-009 表述一致。
- [x] 相同 ID 不同输入的冲突规则与 AC-018 一致，不覆盖原结果且不新增保存。
- [x] 本地 JSON 保存范围与跨进程持久化要求一致，未扩展为生产级或外部持久化服务。
- [x] 动态决策允许预设执行骨架，但不允许以固定分支或自动重试冒充模型决策。
- [x] 真实模型证据与离线 Mock 证据的用途区分一致。
- [x] P0 与 P1 区分一致，失败续跑未被误列为核心阻断条件。
- [x] 需求追踪索引中的编号均能在规格正文中找到对应定义。

## 4. 可测试性与可验证性

- [x] 每个核心场景均有明确前置条件、触发动作和可观察的 Then 结果。
- [x] 正常完成可通过费用比较、时间比较、步骤状态和本地保存结果核对。
- [x] 缺失与非法输入可按具体字段验证，缺预算与缺截止时间仍分别验收。
- [x] 工具失败具有可注入前提，能够检查失败状态、后续动作、成功结果保留和重试费用。
- [x] 保存失败单独验收，能够检查是否存在虚报保存或虚报完成。
- [x] 替代方案验收要求重新估算，并核对历史估算保留但不进入最终合计。
- [x] 预算缺口可以通过最低费用候选方案与预算计算，不再只是验证缺口存在。
- [x] 截止时间等值边界和双重不可行场景具有明确、可观察的判定结果。
- [x] 无素材场景能够核对查询调整、再次检索、素材不足原因和无编造行为。
- [x] 重复执行可通过跨进程重启、原结果一致性、`duplicate=true` 和保存记录数量核对。
- [x] 请求冲突可通过原结果未覆盖和无新增保存副作用核对。
- [x] 保存内容可通过独立读取本地 JSON 核对全部必填信息和实际运行一致性。
- [x] 动态路径可通过两次真实运行的工具观察与后续动作差异核对。
- [x] Trace 字段足够复核工具参数、返回摘要、动作变化和简要依据，无需内部思维过程。
- [x] 执行上限和可选续跑均有明确触发条件与最终状态检查。
- [x] 通用交付验收分别覆盖 CLI 可运行性、测试、证据、文档、提交信息、官方 Pi 包和版本锁定。
- [x] 验收条件不要求检查具体内部实现，只检查外部行为和可审计证据。

## 5. 范围与非目标检查

- [x] 规格聚焦内容活动方案规划，没有混入其他三道项目题的专属业务规则。
- [x] 未要求真实发布、支付、采购、外部平台或外部持久化服务接入。
- [x] 跨进程持久化仅用于本地 JSON 保存和重复判定，未引入生产级数据库或分布式协调。
- [x] 未引入用户规模、性能数值、可用性数值或生产服务等级。
- [x] 未把建议三小时投入误写为系统运行时限或强制完成时长。
- [x] 未将示例仓库视为完整参考答案或达标依据。
- [x] 本阶段只修改规格，没有创建实现代码、测试文件或实际示例结果。
